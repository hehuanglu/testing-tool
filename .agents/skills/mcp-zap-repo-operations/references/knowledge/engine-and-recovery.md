# Engine and recovery mechanisms to recheck

Use under the [knowledge guidance](../operational-knowledge.md). This package includes operational guidance rather than prior-product live checkpoints/results.

## Same version, different schema

Compare actual schema/requiredness/types/auth providers for the receiving deployment. Select compatible executors without extra-schema fields. Versions/tags do not attest source-to-image. Exact method/body needs current execution/readback before observed claims; anonymous capabilities do not establish authenticated sessions.

## Complete findings versus report representatives

Use complete findings for totals where needed, interpreting representative reports accurately and retaining native classification/session/origin. IDs are not globally unique across sessions; retries do not create new findings. Missing paging/filter capabilities mean partial plus focused primitive work, rather than invented offsets.

Reuse zap_assessment.report_reconciliation/collectors. Truncated previews are not full documents; check EOF before nullable nextOffset, using code-point offsets and saved pages for the same artifact. Recheck semantics after add-on/template/filter/version changes rather than assuming all mismatches share a cause.

## Guards and producer budgets

Use actual runtime key/containment constraints before producers and monitor losses during execution. Do not weaken guards/caps to obtain payloads. Engine baselines/controls may consume budgets; inspect actual requests before changing allocations. Failed attempts are not accepted DAST and do not justify universal qualification campaigns.

## Consistent recovery/checkpoints

Keep journals and pending state current during work; recovery saves do not end the session. Readback/reconciliation normally leads to another valuable feasible bounded round using valid existing setup/context. Apply [checkpoint reasons and user guidance](../retention-stop-and-recovery.md#working-session-checkpoints) before an actual handoff; a completed small round alone is insufficient.

Scope reclassification into RUN/ALERTS/SCOPE_ALERTS is offline recomposition, not retest. Retain historical/unretested findings and old responsibility history; newly assigned criteria without observations stay open. Never replay an ACKed mutation or unknown start just to populate new scope reports; use [scope revision handling](../user-security-scope.md#reporting-and-compatibility) and reconcile actual state first.

ACKed mutations followed by selector/assertion failures need ACK/journal/state reconciliation. Preserve failed attempts and identify official continuation/revisions; stale checkpoints do not justify repeated creates/deletes. Latest timestamps do not replace lineage.

After stop/start, reread ephemeral port mappings/client URLs and current scope/identity/binding. New login/preparation after cleanup is a new session rather than old-session resume.

## Media fixture readiness

Negotiation and a successful setup response do not establish that media is flowing or that recording is ready. Verify sender and receiver counters and the expected product state for each media type. Treat capability URLs as credentials when the protocol uses them as authorization.

## Scanner readback and result attribution

Check actual result types and producer state before retrying after a parser error or client timeout. Reconcile terminal status against recorded messages; exclude calibration traffic, unchanged controls and work from a different session or actor. Use atomic replacement when another process reads a shared JSON file.
