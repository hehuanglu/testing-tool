`discover`, `status`, `verify` and `handoff` are offline. `plan` inspects existing deployment metadata and pins; it does not log in or provision fixtures. Outputs use fresh namespaces. Credentials are never CLI arguments. Private actor input is a regular file with no group/other access; each actor binds independent subject/role provenance and credential references. Native private config is mounted only into the owned MCP role; broker sees only actor bindings and admitted wire bootstrap, browser receives only its group job. Final local evidence files are private.

The reviewed recipe is executable through the same finite W3C worker. It cannot contain arbitrary JavaScript, Python imports or user regex. `finalsource-fe-auth/1.0` is an explicit source adapter, with its unresolved branches retained as obligations. Source discovery is not runtime portability. The current runtime control app uses different routes, token storage and protected identity envelope; form-cookie, SSO/MFA and multi-origin support remain unqualified.

UI login is mandatory. Storage injection, API/crawler results and a login label cannot replace it. A session group keeps its browser profile for dependent steps, captures actions/DOM/screenshots, then closes and inventories/disposes its exact profile. Browser and native sessions have separate slots and epochs. Native prepare/validate must run on the admitted canonical origin and prove the independently expected subject. Native login runs while the browser session is open; the next browser protected identity probe checks continuity. Tokens can differ. Browser-auth handles are only usable with Client Spider under the root contract; they cannot be used for active scans.

The authenticated broker reuses evidence2 TLS forwarding and durable request events. Public/bootstrap/probe/protected phases remain distinct. It admits only credentials observed in the appropriate bootstrap and then only the protected identity probe until verified. Wrong actor, unexpected identity, stale/unregistered credential and unknown mutation latch dependent production. App TLS requires CA, hostname and DER fingerprint with canonical Host/SNI. Kernel namespace controls deny browser direct/broker/management bypass. Anonymous policy still rejects identity.

Native active uses owned runtime `tools/list`, direct validated JSON-bearer/form handles, method/body support and bounded native policies. JSON bearer is enabled only in the owned research deployment. Query/body coverage requires an actual changed selected field, fixed siblings, valid protected baseline, native/broker/app attribution and UI/persistence readback. Enabled rules, a scan header, unchanged controls and 401 responses do not prove delivery. UI/direct observations retain separate source attribution.

A lost ACK or uncertain POST/start is never replayed. Stop/export/readback the exact owned resources, preserve intent and app/native counters, and reconcile or retain owned fixtures. Control fault injection must not kill/restart the product or shared scanner. Injected auth loss is not natural expiry. Local logout/storage removal is not server revoke.

Admission is per branch. Missing active/mutation/setup proof does not remove read/passive responsibilities. The verifier reads raw broker events, native history, actor bootstrap/protected responses, DOM/screenshots, report offsets/EOF, passive observations and resource samples. It does not trust worker `passed` or runner exit status. The semantic checker reports workloadCompletion; taskCompletion also requires independent responsibilityInventory. Missing inventory, role, API/input technique or allocation remains partial. Integrity can pass for an interrupted/partial run.
