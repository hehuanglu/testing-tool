# Reporting contract examples

[ALERTS.example.json](reporting/ALERTS.example.json) and [RUN.example.json](reporting/RUN.example.json) are a **synthetic schema example** sharing assessment ID `synthetic-example-contract-v2`. They are neither real scans nor fixture results and contain no actual source, secrets, runtime, or native traces. Synthetic paths/lines need not exist in this skill.

They illustrate a Semgrep-shaped supported observation with manual control review, needs-review with blocked questions/gaps, false-positive with control evidence, and a manual finding with null native fields. Overall partial status differs from illustrative completed rounds/tracks. Three matches/four records demonstrate aggregation, not vulnerabilities; unique_issues remains null pending triage. Execution command/version/exit/timestamps/counters remain null because no scanner ran.

Flow steps are manual, rather than invented native-dataflow. Synthetic provided-policy references differ from source assumptions. Use real observed data for actual reports without copying claims/counts/verdicts. See [reporting](../references/reporting-and-completion.md) and [evidence](../references/evidence.md).

RUN includes `coverage.inventory_candidate_reviews`, null checkpoint timestamps, and illustrative `tracks[].review` process/evidence/dependency notes with no real review time. The four-track example demonstrates base v2 records. New assessments follow the [criteria workflow](../references/criteria-workflow.md) and add the [criterion fields](../references/reporting-and-completion.md#criterion-records).

For a synthetic delivery walkthrough, map a search-input criterion to `Q-01` and an input-and-session criterion to `Q-01` plus `Q-02`. Assign issue ID `ISSUE-01` to finding `F-01`. It contributes once to each criterion and once to the workbook total. The second criterion has partial coverage, a confirmed issue, and an open session question with `F-02` needing review. Both criteria cite the relevant evidence IDs for `F-01`. The wider criterion also links the session evidence and the missing effective configuration. The example's source paths and revision are placeholders, so the workbook projection uses labeled synthetic locations.

[round-spec.example.json](reporting/round-spec.example.json) is collector input: replace paths/purpose/source state and configure the process environment before use. Never execute unchanged placeholders. The [serializer](../scripts/report_records.py) creates undecided drafts/questions; the [checker](../scripts/check_report_links.py) checks bookkeeping rather than semantic truth.
