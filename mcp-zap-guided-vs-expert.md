# MCP ZAP Guided vs. Expert

The two runtime inventories came from the same image and byte-identical JARs. **Guided exposed 21 tools, Expert exposed 78, and all shared input schemas matched.** The engine images matched as well. Persisted Guided state and fresh Expert state contained different versions of several add-ons, so engine-specific results below describe the tested deployment. ## What requires code

No MCP implementation change is needed to use the verified Expert workflows. A digest-pinned Expert deployment, matching engine/add-ons, a shared workspace, and local fixtures were sufficient. A comprehensive MCP-managed lifecycle would need additional operations for context/user deletion, separate plan validation and cancellation, and typed sanitized evidence and verdicts. Use standalone Automation Framework when native plan validation and process exit are the relevant gates. Use application-owned assertions for auth identity, authorization, response semantics and application state. These two execution paths can share an evidence format with MCP.
