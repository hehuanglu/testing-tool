# M0 decision log

Source of truth: ../../MCP_ZAP_SKILL_LONG_TERM_OPERATING_PLAN_VI.md v2.0; no changes to gates.

- **ADR-001 Runtime:** Python 3.13, JSON Schema 2020-12, stdlib unittest and Docker CLI. Upstream Java requires JDK25, whereas the operator default is JDK11. Use the already present, digest-pinned v0.16.0 runtime; do not build the dirty Java checkout. Exact Python dependency versions are in requirements.lock. No new scanner engine/queue/report service.
- **ADR-002 Isolation:** each run owns four labeled containers and a fresh ZAP filesystem/session. Network namespace starts with `--network none`; no host ports, Docker socket, host management endpoints or external DNS. UID1000 scanner can create TCP connections only to the mandatory origin guard at 127.0.0.1:18888; UID1001 MCP only to ZAP:8090; UID1002 control client only to MCP:7456/ZAP:8090/guard:18888. UID1003 guard/fixture can connect only to fixture:18080. Direct scanner/adapter sockets to the target are denied. The guard accepts anonymous GET for the exact http://127.0.0.1:18080 origin, checks Host, rejects CONNECT/HTTPS/aliases and forwards to a fixed IP without DNS or redirect following. A shared send lock enforces the approved 1–2 requests/s across preflight and scan traffic. Established replies allowed. IPv6 outbound drops. Firewall is installed before any target/scanner process starts. Kernel counters plus a live forbidden port canary verify boundary. Browser is unsupported and never launched.
- **ADR-003 Authority:** product profiles reference a separate registry. Only the built-in isolated-fixture harness can currently be executed. Synthetic authority derives from the explicit user authorization to build/run isolated fixtures (2026-10-18), applies to fixed namespace loopback, one runner, ≤2 requests/s, ≤30 minutes, read-only fixture crawl/import/GET seeds. A staging label or inline owner cannot make a product executable. Product execution remains blocked pending owner/issuer, exact origins/IPs, environment proof, approved operations/destructive level, validity/budgets, retention and reviewer. No product credential is needed or read for this work.
- **ADR-004 Secrets:** authMode=none only, no credential resolver or auth tool allowed. JSON/Bearer/form/browser remain unsupported. Isolated synthetic MCP/ZAP explicitly use no API credential within the private namespace; this avoids introducing infrastructure credentials into commands/logs. Public report/summary publication rejects exact configured canaries (including encoded forms) and credential-like patterns. This does not claim authenticated secret-gate coverage. No secret store or existing .zap-auth file is opened.
- **ADR-005 Scope:** V1 supports one canonical literal-loopback attack origin and no browser dependencies. Planner validates every OpenAPI servers list/ref and exact GET operation inventory before side effects; external refs rejected. Adapter checks scope at each send and disables automatic redirect following. The mandatory origin guard checks every forwarded HTTP request, including redirects, and rejects scheme/hostname/Host changes on the same endpoint; the scanner firewall blocks bypass, control endpoints, DNS and IPv6 at send-time. Product DNS/HTTPS host support is deliberately unsupported pending additional tests, rather than implied by a generic URL validator.
- **ADR-006 Lifecycle/recovery:** immutable canonical plan, append-only SHA-256-chained/fsynced intent and ACK journal, deterministic run/container names, exclusive ownership lock. Direct guided upstream idempotencyKey is ignored; starts/imports never retry. If ACK is lost, stop/reconcile the entire dedicated namespace rather than generate another scan. Process restart recovery is stop-only, preserving incomplete evidence. No attempt to reconstruct signed guided IDs or resume anonymous/credential context blindly. Failed stop retains lock and quarantine; no scanner/session reuse. Borrowed containers are never adopted. No whole-volume/target reset.
- **ADR-007 Evidence/status:** distinct execution/evidence/verdict/cleanup/gate fields; untriaged medium/high alerts require review, operational/integrity failures block. Only complete required evidence and coverage can allow. Report code-point offsets/UTF-8 SHA-256 verified; local staging publication uses atomic rename and readback. Manifest digest detached. Frozen evidence journal ends at EVIDENCE_READY; operational journal records FINALIZED after publication. No reviewer approval is generated. Coverage claims anonymous GET response assertions, not active rule/JS/auth coverage.
- **ADR-008 Storage/host:** local per-run directories, restrictive run parent/staging permissions, synthetic fixture/workspace subdirectories writable only inside private run root. Synthetic retention is recorded as 14 days; no deletion scheduler or automatic existing-data cleanup. macOS+Docker Desktop is the measured operator host; Linux CI remains unverified. GA/storage durability/SLO/independent review belong to later milestones.
- **ADR-009 Required tracks/budgets:** explore-public (HTTP) and api-schema (self-contained OpenAPI 3.0 JSON) required. Runtime spec, authentication and business ownership require current discovery. Active scan is optional in the canonical roadmap, outside the required fixture pilot; the current planner blocks it until an actual capability campaign verifies it. Defaults total1800/crawl300/active900/settle300/stop120/poll1 seconds, stable backlog observations≥2, one runner/namespace. Rate policy must be configured and read back or run blocks.

No hidden assumption grants product scanning authority. Reviewer identity and product retention are unresolved owner decisions; they do not grant a synthetic sign-off. G0 covers the documented synthetic technical baseline only.

Origin-guard correction: development campaigns using IP/port firewall alone do not prove exact-origin enforcement. They are retained as development evidence; only the final campaign with mandatory proxy readback, guard probes and kernel bypass denial supports G2. The shipped release image has a server-name OCI label but no revision attestation; the inspected source tag and observed image version/digest are recorded separately, without claiming a verified source-to-binary attestation.
