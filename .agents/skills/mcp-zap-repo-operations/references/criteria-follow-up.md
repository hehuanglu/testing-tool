# Follow-up planning and execution

Apply this loop after case readback, on resuming an incomplete assessment, or when concrete evidence challenges a prior applicability or coverage decision. Use the [v3 workflow](criteria-driven-workflow.md) and [managed state](retention-stop-and-recovery.md#operator-schedule-and-crash-checkpoint) as the authority for approvals, execution and completion.

1. **Reconcile by criterion.** Resolve the committed generation and read the current plan, relevant earlier plans, case results, semantic evidence and pending operations. For each affected criterion, identify the exact obligation, what compatible observations already establish and what is still missing. Check target, build, actor, fixture/state, method and observed outcome against the obligation. Preserve historical verdicts and evidence. A genuine scoped absence can retain `Not applicable`; a demonstrated applicability error warrants a reviewed revision, and unknown applicability or missing evidence remains pending. Reconcile an uncertain prior effect before scheduling anything that could replay it.
2. **Plan the remaining work.** Specify the criterion and case IDs, missing observation, expected outcome, evidence required for closure, executor and dependencies. Use shared work where context and method match. Distinguish new work from compatible evidence already available, and record concrete resumption conditions for blocked work. A follow-up can be a bounded work allocation within the existing plan. If the change requires a revision of the approved criteria or plan, use the preparation subagent and coordinator review, carry forward all 50 selection decisions with explicit changes, and bind Gate 2 to the revised content before executing the changed work. Preserve historical approvals and rebase the managed schedule. Fixture, reader and equivalent executor adjustments within the approved envelope use the existing allocation and journal contracts.
3. **Execute, read back and reassess.** Select eligible work from managed state, apply normal admission, and retain the intent, receipts, semantic readback and per-case decision. Compare the new and compatible prior observations with each affected criterion's `all_cases` obligations. If an operational failure is recoverable, read back the original attempt, repair the affected dependency and retry only the missing work when safe under [local continuation](local-remediation-and-continuation.md). Keep blocked work pending with its dependency and continue independent eligible work.

   A receipt with an ACK, message ID or response hash can locate a prior observation. A branch-level requirement also needs the relevant response fields or equivalent semantic readback. If the raw result is retained only in the scanner, identify the original session and message, and verify that the retained result matches the receipt and evidence context before reusing it. If it cannot be recovered, record the exact readback gap before considering a new operation.
4. **Repeat and publish.** Revisit remaining obligations after each reviewed batch. Close criteria individually when their evidence supports a verdict. Reconcile resources and verify delivery to the same Sheet under the existing completion and reporting rules.

## Acceptance of changes to this loop

Exercise a retained assessment with an actual unresolved obligation or a challenged historical verdict. Check prior evidence reuse, the exact remaining action, approval routing and the reviewer outcome. Include a control whose earlier conclusion remains supported. If a failure occurs, correct the affected planning or execution step and repeat the check against the same retained baseline. Use a separate draft or isolated state for offline review. Record which steps used retained evidence, which ran through the state/review helpers and which would require approved live execution. See [operational validation](operational-validation.md).
