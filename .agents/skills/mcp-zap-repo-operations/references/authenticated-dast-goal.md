# Carry authenticated DAST through to execution

Use this technique only within the approved [criteria-driven plan](criteria-driven-workflow.md); it adds no track-wide assignment or alternative workflow. User delivery follows the [Drive table contract](single-table-drive-output.md); JSON/native artifacts below are internal working data.

The goal is real protected-API ZAP testing with correct roles and valid sessions across the full assigned inventory. Direct BOLA, anonymous reports, health/login checks, and skill changes do not fulfill it.

Necessary private local credential/token retention is authorized with notification; reflect it in research-profile retention fields. Select compatible authorized deployments without enabling shared experimental features or exposing secrets.

Discover APIs/roles/inputs/fixtures → select actual operations/entries → bounded workload → auth prepare/validate/crawl/attack/status → read results. [Dispatch](operation-dispatch.md), [multi-product](multi-product-backend.md), and applicable [research](be-authenticated-research.md) guide selection rather than mandate one executor. Root method/body fields differ from wrapper support. Do not fall back automatically to strict historical/foreign-product runners or add proof/qualification/hash campaigns; preserve actual gates and identify their concrete dependencies.

Diagnose actors, fixtures, input mappings, vectors, runtime, and reporting separately under [remediation](local-remediation-and-continuation.md), preserving full scope/independent branches. Wrapper rejection is neither product failure nor global ZAP impossibility.

For skill-only assignments, inspect baseline/user limits, edit routing/workflow, validate links/structure, and walk through offline. Do not scan products or change unrelated schemas/implementation to prove documentation changes.

For actual assessments, execute authorized ZAP, monitor terminal/auth loss, inspect findings and relevant mutation results, and record actual methods/routes/roles/techniques. Seed is not active and lost sessions are not coverage. Reconcile protected inventory after meaningful rounds and continue eligible gaps autonomously across bounded rounds, reusing valid actors/fixtures/runtime. Persist recovery state throughout; [checkpoint](retention-stop-and-recovery.md#working-session-checkpoints) with concrete next actions only for a stated handoff reason. The goal may span work sessions; preparation progress and known nonterminal operations can be handed off without inventing completion/blockers. On resume, reconcile unknowns and selectively revalidate actor/fixture/runtime dependencies before further effects. [Handoff](product-assessment-handoff.md) preserves actual results/open duties without evidence folders or unassigned lifecycle qualification; incomplete obligations prevent full completion.
