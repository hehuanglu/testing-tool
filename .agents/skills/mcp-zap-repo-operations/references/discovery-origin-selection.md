# Select execution origins

For new products/backends, begin with the [common workflow](multi-product-backend.md). Source-only work needs no fabricated environment/frontend; source/control proof does not qualify runtime. Legacy finalsource/CLI guidance applies only within its stated compatibility scope.

Apply [scope](criteria-driven-workflow.md): inventory/provenance → user/discovery responsibilities → admitted workload → reconciled results. Origin/admission failures block dependent execution without deleting routes/business/ownership obligations. Preserve source-only plans/dependencies; do not fabricate deployment or trust historical bindings.

Keep all discovered aliases. For manifest 1.1/plan 2.1, independently inspect **all** authorized+bindingVerified candidates per role against the same target binding before traffic. An invalid alias rejects admission; do not fall back silently.

Compiler, native auth profile, direct fixture client, and cleanup select the first valid candidate in manifest order per role. Plans lock scanner origin and admission detects selection drift. Reordering changes selection/hash and requires a new plan. Context, seed, active, controls, whitelist, and guards use that origin. No product-specific default alias/origin exists.

These are transformation/consumer rules: do not add oracle facts, remove frozen aliases, or edit locked provenance to pass admission. Preserve pinned discovery references; change separate consumer-policy references when appropriate. Manifest 1.0/plan 2.0 and research v1 retain their old contracts.

[Anonymous FE research](fe-anonymous-research.md) has a separate transport/journey lane; do not force it through backend HTTP binding. Backend-only prerequisites remain unchanged.
