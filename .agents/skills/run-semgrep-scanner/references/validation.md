# Validation and verification limits

## How to validate maintenance

Check actual relative Markdown files/anchors and frontmatter/UI YAML. Parse the [synthetic report pair](../examples/README.md) and reconcile IDs/counts/provenance/source states/statuses/backlinks without calling it a real scan. Use existing local parsers/help rather than installing dependencies or fetching remote validation rules merely to pass.

Run helper tests and the example checker where relevant. [offline-rule-lints.yml](offline-rule-lints.yml) checks only fix/fix-regex. Actual [fixtures](../tests/README.md) compare complete positive/negative positions and inspect exits/errors/skips/timeouts/scanned paths; skipped files are not semantic negatives. Match test scope to changes, then inspect baseline/diff before intentional installation updates. Preserve private/custom content via the installer backup contract.

## Decision scenarios

Review unsupported Python/Java/Go against applicable local/custom/manual options rather than zero TS matches; unfamiliar wrappers/owners through actual models/principals/criteria; alternate Compose filenames through consumers/path limits; JWT decode against same-token verification/global guards; missing policy against labeled source hypotheses and threshold heuristics; native traces versus manual provenance; zero matches with missing paths; timeouts/partial output with feasible remediation; and filter/rule/ignore changes during retests.

Supported issues do not prevent scope completion, whereas required unfinished needs-review triage does. Candidates-only assignments retain their narrower claims. Blocked-before-scan findings may be empty while native counts remain null. Review criteria and Sheets mapping, including one issue shared by several criteria, partial coverage with a confirmed issue, runtime-only gaps, missing native fields, and permalink/source-state mismatch. Check that a Semgrep issue confirmed manually counts once in its risk bucket, an agent-only violation counts in Only observed and may support Fail, and an unresolved match contributes neither count. Check all four statuses, including partial evidence that cannot establish Pass and rows excluded by the user. Check that failed Sheets delivery keeps an assessment resumable from private records. Execute feasible next steps rather than stopping after writing next_step.

For planning changes, review a broad draft with a read/write ownership split and a relevant config path omitted from the scan plan. Check that the coordinator identifies both, returns specific questions to the preparer, and verifies revised question, path, method and closure mappings. Check that missing policy or a runtime-only question remains open and that targeted/retest routes retain their bounded scope. For ledger changes, remove a known result index from a criteria report, retain an unknown count in another round, and check the historical sample for compatibility. A planning walkthrough and bookkeeping regression tests verify different parts of the workflow from a new product assessment.

For follow-up planning acceptance, use a reviewed partial RUN with both a supported issue and bounded negative conclusions. Reconcile the proposed revision against every open question, including those criteria. Check a mixed source/runtime question for an executable source check and an exact external dependency. Verify that the same preparer drafts and revises the supplement in response to concrete coordinator feedback. Walk through the initial plan, focused scan or retest, and supplement. Each presentation ends the turn. General or delegated authorization and approval of an older revision leave the presented plan pending. Approval of the exact revision resumes all feasible work, including independent items and routine retries. A planning-only run leaves actual coverage, rounds and conclusions intact.

For independent operation, verify that an assessment sharing criterion IDs with a ZAP run can reuse selection decisions alone. Review a mixed report with a runtime-only finding and a directly supported source finding. Check that the corrected RUN, ALERTS and Sheet reopen the runtime-dependent criterion, exclude that finding from counts, and retain the supported source finding.
