# M2 existing Docker target — public/API only

Run from this package checkout, Python3.13/.venv, with Docker Desktop available. Runtime images/helper IDs in `profiles/runtime-baseline.json` must already exist. Do not build the dirty upstream JSON/Bearer checkout or reuse an existing ZAP session. Everything is foreground; no automation/service is installed.

## Supported binding

`docker-existing-http-v1` borrows one running Docker container on a local bridge network, exact literal IPv4 HTTP origin and approved GET path list; one runner, one owned scanner/session per run, no auth or active scan. Container ID, image ID, StartedAt, network ID and address must match owner-approved `bindingHash`. Product application mounts are unsupported because image-only identity would not cover their contents. Public health JSON pointers supply the application oracle. Identity is host-side container metadata plus declared health assertions, not a TLS or cryptographic application attestation.

HTTPS, DNS names, IPv6, browser/JS, dependency origins, auth, dynamic/protected operations and external schema refs are rejected. No protocol downgrade, CA bypass or source URL fetch. Schema is an adjacent canonical JSON file with a pinned hash; only approved public GET operations, no callbacks/webhooks/links/external refs. A full Swagger document is not automatically a permitted public subset.

The owned namespace initially has only inert sleep PID1. Docker cannot connect its special `none` network to a bridge, so the owned anchor attaches directly to the approved bridge; DROP firewall rules are installed before any scanner, MCP or guard process starts. Nothing in this phase sends an application request. INPUT drops non-loopback/new external connections. UID1000 ZAP can connect only to loopback guard18888; UID1001 MCP only to ZAP8090; UID1002 adapter only local management/guard. UID1003 guard can connect only to the exact approved target IP/port. DNS/IPv6/metadata/external sockets are blocked. Management listeners bind loopback. The guard checks exact origin, Host, GET path, authority expiry, rate and credentials on every request; redirects must pass the same checks. Requests with credentials are refused and response Set-Cookie/WWW-Authenticate is rejected before reaching ZAP history. Response Server/Date is guard-generated, a report provenance limitation.

Upstream content import requires a dedicated POSIX shared root. Each run owns a labeled Docker staging volume at `/tmp/zpa-imports`, writer UID1001, group1000 read, mode0750; MCP sees a named non-login UID1001 account via a run-owned read-only passwd file. ZAP has a read-only mount. This preserves the pinned upstream writer lock/permissions rather than weakening them. Content/report/automation roots are separate.

## Pilot (only after all owner and binding gates)

```sh
PYTHONPATH=src .venv/bin/python -m zap_assessment.cli pilot \
  --product profiles/product.owner.json \
  --authority profiles/product.authority.owner.json \
  --expect-plan-hash REPLACE_WITH_VALIDATED_PLAN_HASH
```

The draft authority has missing timestamps and unresolved owner/issuer/evidence; validation fails before runtime creation. During a permitted pilot, sideplane preflight checks borrowed identity before creating scanner resources, guard acceptance/proxy/rate readback is mandatory, health assertions precede crawl, then content import and individual GET response assertions, passive settle, full chunk/hash readback, cleanup and atomic bundle publication. Only declared GET coverage is measured; health-only coverage says nothing about authenticated API/business or frontend/JS behavior.

Exit0=allow in declared coverage, 1=confirmed failure/block, 2=incomplete/operational block, 3=review_required. A medium/high alert keeps review_required. Verify returns artifact integrity status, not reviewer/release approval:

```sh
PYTHONPATH=src .venv/bin/python -m zap_assessment.cli verify runs/RUN_ID/bundle
PYTHONPATH=src .venv/bin/python -m zap_assessment.cli recover runs/RUN_ID
```

Ctrl-C attempts cancellation/owned cleanup. Process interruption or lost ACK uses stop-only recovery, never scan/import replay. Deterministic resource IDs, creation intent, labels and container/volume identity reconcile an uncertain creation ACK. Confirmed stop/removal covers only owned containers and content volume; no target stop/remove/exec/restart/reset or borrowed-network removal. A missing/changed target blocks assessment, but does not prevent cleanup of owned scanner. Unconfirmed stop/ownership mismatch retains quarantine+lock. Secret-integrity quarantine needs owner incident disposition; generic recovery cannot export/clear it. Do not auto-expire, purge or recreate any target/run/baseline.
